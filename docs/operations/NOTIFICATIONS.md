# External notification delivery

The worker processes durable encrypted intents outside business transactions. In-app delivery is local. EMAIL and MOBILE use separately configured HTTPS gateways; no commercial provider has been selected or silently provisioned. Real external delivery remains a release gate until a gateway adapter is implemented by the selected provider integration and tested end to end. Empty configuration fails visibly as `provider_not_configured`; it never pretends delivery succeeded. Keep real provider configuration absent on the protected synthetic demo.

Gateway contract: authenticated POST with Bearer credential, `Idempotency-Key` equal to the immutable intent UUID, JSON `{ id, channel, recipient, subject, text }`. The gateway MUST durably deduplicate that key for at least the full retry/replay retention period, including uncertain timeouts, and return success only after durable provider acceptance. A duplicate accepted request returns success without sending again. HTTP 429/5xx and transport timeouts are retried, at most three recorded attempts with BullMQ backoff. Other failures are terminal and visible to administrators. `DELIVERED` means gateway acceptance, not confirmed recipient receipt. If receipt tracking is required, extend the contract after provider selection; do not claim SMS or inbox delivery from an HTTP acceptance alone.

Credentials live in the deployment secret store/environment. Requests time out after 10 seconds; redirects are forbidden. Neither payloads nor provider response bodies are logged. Authentication links put tokens in URL fragments. Expired/consumed identity tokens are never sent. MOBILE_VERIFICATION is sent to the registered mobile channel; status SMS requires a verified mobile. Failed historic intents are retained and are not mass-replayed automatically. Investigate failures before a targeted operational replay; expired verification links require issuing a fresh token.

The gateway boundary is prepared and testable, but is not a substitute for choosing email/SMS providers, sender verification, mobile delivery registration and testing real deliveries in separated staging.
