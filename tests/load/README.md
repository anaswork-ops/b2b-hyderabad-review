# Phase 8 representative capacity workload

Run the pinned k6 image against isolated staging only. Supply 500 unique authenticated synthetic business sessions in a private JSON fixture file, each containing `token`, `csrf`, `slug`, two `packageIds` and an owned `conversationId`. Never commit that file. The harness refuses missing explicit isolation acknowledgement or fewer than 500 fixtures.

Ramp to 500 concurrent active virtual users over 30 seconds, hold for three minutes (override HOLD_DURATION for longer qualification), ramp down over 15 seconds. Each user performs real requests with 3–7 seconds think time (reading results and entering enquiry text): 50% filtered/date/vertical marketplace searches; 20% public business detail; 10% authenticated session; 10% protected comparison; 5% inbox; 5% message writes. Set API_BASE, FIXTURES, ALLOW_ISOLATED_LOAD=1 and SUMMARY_PATH. Thresholds: error rate <1%, successful checks >99%, normal API p95 <=1 second, search p95 <=2 seconds.

For a local single-generator run, EMULATE_INGRESS=1 sends distinct forwarded client addresses. Trust those headers only on the isolated test server, never relax production ingress for testing. This preserves realistic per-user abuse limits instead of disabling them. A production qualification run must use the actual trusted ingress and production-equivalent infrastructure, representative data cardinality and repeated/longer holds. Capture CPU/memory, workload version, dataset size, thresholds and raw summary. A workstation result alone is not a production capacity guarantee. Fixture setup and all message writes must target a new isolated database. No demo credentials or database are load-test targets.

The more aggressive stress variant sets THINK_MIN=1 and THINK_SPREAD=2. Both results must be reported; a pass at 3–7 seconds does not establish the same latency at 1–3 seconds. The initial local stress runs failed normal API latency. This workload assumption must be validated against observed launch traffic; it is not a promise of unlimited request throughput. API_BASES optionally distributes users across a comma-separated list of API instances sharing one database and Redis namespace.


## Reproduction

Restore a synthetic backup into a NEW `b2b_restore_*` database using the guarded restore utility. Point DATABASE_URL at that clone and run `ALLOW_ISOLATED_LOAD=1 node tests/load/prepare.mjs` using your shell's environment syntax. This adds 500 non-login synthetic owners/businesses/sessions/conversations only to the clone and writes ignored `.local/load/fixtures.json`; it refuses an existing fixture file. The clone must contain two published packages and an approved profile. Run compiled API instances with that clone, a separate Redis namespace and object bucket. Supply the private fixture path to k6. Do not enable real external providers. Fixture session lifetimes are eight hours; deliberately archive and regenerate them for later test runs. Retain summaries, server logs and environment capacity with the release evidence.
